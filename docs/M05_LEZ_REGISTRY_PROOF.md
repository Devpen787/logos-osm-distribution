# M05 — Minimal LEZ OSM Registry Proof

## Goal

Create the smallest credible on-chain OSM registry foundation required by LP-0018.

Required entry fields:

- `region`
- `parent`
- `level`
- `cid`
- `source_url`
- `checksum`
- `version`
- `hosted`
- `timestamp`

## Architecture

```text
crates/osm-registry-core
  deterministic state + validation + queries
              |
              v
methods/guest
  thin SPEL PDA + instruction wrapper
              |
              v
artifacts/osm-registry.idl.json
  generated interface contract
```

Keep business rules out of the guest wrapper when they can be normal Rust.

## Registry model

The registry stores exactly one **current** entry per Geofabrik region path, matching LP-0018's requirement that `region` is unique.

Identity key:

`region`

Rules:

- replaying the same snapshot/status is idempotent even if the caller observed it at a later registration time;
- a different snapshot for an existing region may replace it only when its registration timestamp is newer;
- source-version downgrades fail closed;
- parent/level for an existing region cannot change;
- the same region cannot appear twice in one batch;
- the stored registry vector is ordered by timestamp descending, then source version descending, then region ascending.

This keeps the current registry compact and makes central-version vs registry update checks unambiguous. Historical archive semantics are intentionally out of scope for M05.

## Parent semantics

- country: `parent = None`
- subregion: `parent = Some(<registry-country-id>)`

This is the LP-0018 registry tree, not necessarily Geofabrik's source-index parent. M03 already separates those concepts.

## Guest interface

One PDA:

`osm-registry`

Instructions:

1. `init_registry`
2. `register_batch`

Batch arguments are parallel primitive vectors because current SPEL CLI support is strongest and most interoperable for those types.

Level encoding:

- `0` = country
- `1` = subregion

For country entries, an empty string in the guest's `parents` vector is normalized to `None`.

## Queries

M05 core exposes:

- `by_region`
- `by_parent`
- `by_cid`
- `latest_by_region`

The on-chain state is queryable by fetching/decoding the registry PDA. A richer client API belongs in M08.

## Proof sequence

1. normal workspace tests for registry rules;
2. standalone guest tests;
3. generated IDL equals committed IDL;
4. build RISC-Zero guest binary;
5. local standalone LEZ/sequencer:
   - initialize registry;
   - register Ethiopia using the real M04 Storage CID;
   - register a second batch;
   - fetch/decode registry state;
   - prove region/parent/CID query semantics from decoded state;
   - prove timestamp ordering;
   - prove identical replay is idempotent;
   - prove a newer region snapshot replaces the prior current entry;
   - prove stale/conflicting replay fails atomically.

## Exit gate

M05 is locally verified only when:

- core tests pass;
- guest tests/compile pass;
- IDL is generated by pinned SPEL and freshness-checked;
- local standalone LEZ execution mutates and decodes the PDA as expected;
- batch replay/conflict/timestamp behaviors have raw evidence.

Testnet remains explicitly unverified until M11.
